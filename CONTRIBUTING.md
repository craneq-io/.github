# Contributing to CraneQ

Open a focused pull request against main. Use a Conventional Commit subject, sign off your own commits with `git commit -s`, and credit co-authors accurately. Include the reason for the change and how you checked it. A code owner reviews the change before squash merge.

For a source update, identify its publisher, citation, edition, checksum and effective dates. For a rule change, link the source revision, explain the interpretation and include fictional cases that exercise the boundary. Flag interpretations that need domain review. Keep taxpayer information, account details and credentials out of examples and reports.

Maintainer build and test gates run in containers through Yureisha. Pin build dependencies and verify their origin. The website uses GitHub Pages branch publishing.
